# Decision Record

## Document Status

**Existing full-record structure; fill it only after actual approval.**

## Purpose and Use

Prepare the full DEC record for Decision History and summarize it in the chronological Decision Log. A blank record or a Confirmed placeholder cannot approve a proposal.

- **Owner:** Paul develops the recommendation; record the actual approver and any established implementation owner.
- **Trigger:** Staff or pastoral direction has been supplied with source, date, and approver.
- **Variables / inputs:** Next DEC identifier, actual decision/status/date/domain, supported supersession links, named owner/approver, evidence, implications, and boundary.

## Record Template

```markdown
### DEC-XXX — Title

- **Decision:** What was approved?
- **Status:** Confirmed
- **Date:** When was it approved or recorded?
- **Domain:** One primary taxonomy domain
- **Supersedes:** Earlier DEC identifier, if explicitly supported
- **Superseded by:** Later DEC identifier, if explicitly supported
- **Owner:** Implementation owner, if one is named
- **Approver:** Who approved it, if recorded?
- **Evidence:** What meeting, document, or direction supports it?
- **Implications:** What ministry work changes?
- **Boundary:** What does this not authorize or settle?
```

## Before Use

- [ ] Confirm the actual stage, permitted use, and source evidence.
- [ ] Replace placeholders; keep confidential participant, pastoral, screening, and safeguarding details out of the vault.
- [ ] Record completion only when the action actually occurs; a template grants no approval.
